# 共通作業引き継ぎプロトコル v1.0

## 基本原則

外部自由領域では、AIの会話状態ではなく、作業記録を引き継ぐ。
どのAIでも同じ作業を再開できるよう、作業ごとに Work Object を持つ。

## 作業開始フロー

1. BOARD を確認する。
2. アドミンに対象作業を確認する。
3. 該当 Work Object を読む。
4. 前回の last_action と next_action を確認する。
5. 必要な references のみ読む。
6. 作業を開始する。

## 作業終了・中断フロー

作業を終える、AIを切り替える、または途中で中断する場合、担当AIはアドミンへ以下を渡す。

- work_id
- 今回実施したこと
- 得られた結果
- 変更したもの
- 現在地
- 次に行う具体的作業
- 未解決事項
- 新たに必要になった参照先
- 人間確認が必要な事項

アドミンは受け取った内容を Work Object と BOARD に反映する。

## アドミンの責任

- 最新の作業状態を維持する。
- 前AIの作業内容が次AIへ伝わる状態にする。
- BOARD と Work Object の不整合を確認する。
- 参照先を整理する。
- 作業の方向性が不明な場合は確定せず、未解決として残す。

## 各AIの責任

- 作業開始前にアドミンから引き継ぎを受ける。
- 前回記録を読まずに既存作業を作り直さない。
- 作業終了時にアドミンへ実施内容を返す。
- 自分が参照できない情報を参照済みとして扱わない。

## 参照先の扱い

GitHub、Notion、Drive、社内DB、その他の外部保存先は詳細資料・正本・成果物の保管先として扱う。
外部自由領域には、必要な参照先と現在状態を残す。

## 完成条件

別AIが、ユーザーから詳細説明を受け直さなくても、BOARD、アドミン、Work Object、参照先を使って前回の続きから作業できること。
