# ナビィ起動時引き継ぎプロトコル v1.0

## 目的

ナビィは、各AI環境でユーザーの案内役として動く。
新しい指示を受けた場合、既存作業の続きである可能性を先に確認し、前AIの作業を無視してゼロから始めない。

## 起動時の必須順序

1. ユーザーの依頼内容を確認する。
2. 外部自由領域の共有掲示板を確認する。
3. アドミンへ関連作業の現在状態を問い合わせる。
4. 該当する Work Object を読む。
5. 前担当AIが最後に行った作業を確認する。
6. current_position / last_action / next_action / unresolved / references を確認する。
7. 詳細情報が必要な場合のみ、GitHub、Notion、Drive、社内DB、その他の参照先を読む。
8. 引き継ぎ内容を理解してから作業を開始する。

## ナビィがアドミンへ確認する標準項目

- この依頼に関連する work_id はあるか
- 現在どこまで完了しているか
- 前のAIは何を行ったか
- 次に何をする予定だったか
- 未解決事項は何か
- 参照すべきファイル・URL・正本は何か
- 人間確認が必要な項目はあるか

## 新規作業の場合

既存の作業オブジェクトが存在しない場合は、新規作業として扱う。
ナビィは目的を整理し、アドミンへ新しい Work Object の登録を依頼する。

## 原則

- 作業開始前に引き継ぎ確認を行う。
- AIの内部記憶だけを引き継ぎ元にしない。
- 外部自由領域の作業記録を共通基準とする。
- 詳細資料を最初から全部読まず、必要な参照先だけ読む。
- 不明点は推測で埋めず、アドミンまたはユーザーへ確認する。

## 最優先

どのAIを使っても、前回の続きから同じ方向性で作業を再開できる状態を作る。
